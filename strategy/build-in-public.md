# Build in Public 在中国企服市场的稀缺性

## 中国企服市场的默认规则

企服务采购的典型路径是：听说某家公司做过类似项目 → 托人牵线 → 签 NDA 才能看案例 → 比价 → 靠关系和服务承诺做决策。

这个路径依赖一个前提：**供应商的过程质量是不可见的。** 你不知道对方的交付标准是什么，不知道他的项目管理和你有多少差距。你只能看销售的口才、已交付客户的品牌、老板的交情。

所以企服公司的默认策略是：销售驱动、案例包装、关系维护。所有关于"我们怎么做"的知识藏在自己手里，因为这是谈判筹码。定价是一客一议——价格取决于谈，不是取决于规则。这是信息不对称越深、谈判空间越大的逻辑。

## 我们选的另一条路

我们的做法和行业默认逻辑相反：

**公开过程质量，而不是公开结果。**

大部分企服公司会公开案例——"我们帮 X 公司做了 Y 项目，效果是 Z"。但这是结果，不是过程。结果可以包装，可以挑好看的讲。

我们公开的是过程——需求怎么拆解的、验收标准怎么定的、执行中遇到了什么问题。这让客户不需要靠销售吹嘘来评估我们，看仓库就够了。这不是"更透明"，这是**把评估权从销售手里移到了客户手里。** 在中国企服行业的卖方市场逻辑下，这是逆势的。

**公开规则，而不是公开关系。**

我们的模式是公开报价逻辑、公开验收标准、公开交付物要求。这切断了"靠信息不对称赚钱"的路径，但也意味着每一个报价都可以被客户拿去跟其他供应商对比。如果我们的价格不是最优的，客户一眼就能看到。市场竞争从谈判竞争变成规则竞争。

**公开失败，而不是只公开成功。**

中国企服行业最忌讳的是承认失败。案例必须完美，过程必须无瑕。我们的日记里记录真实过程，包括做错的部分。这不是因为我们不在乎形象，而是因为在普遍只展示成功案例的市场里，愿意展示真实过程本身就是一种筛选信号——它过滤掉那些期望完美交付但不愿意为过程质量付费的客户。

## 稀缺性的来源

| 维度 | 行业默认 | 我们的做法 |
|------|---------|----------|
| 评估依据 | 关系 + 案例包装 | 公开标准 + 项目档案 |
| 定价方式 | 一客一议，谈判确定 | 公开规则，公式计算 |
| 失败处理 | 隐瞒或推诿 | 记录在日记里，公开复盘 |
| 客户认知 | 判断"这个人靠不靠谱" | 验证"这套规则是否被一致执行" |
| 竞争对手反应 | 靠关系抢客户 | 靠规则竞争，但需同样深度 |

稀缺性不在于"公开"本身——公开谁都可以做。稀缺性在于：**公开后你还敢把规则执行下去，并且在执行中发现的问题是公开修正而不是内部掩盖的。** 这需要规则体系本身经得起外界审视。

在大多数企服公司，流程文档是拿给客户看的，不是自己执行的。我们反过来——流程文档是自己执行的，公开给客户看只是副产品。这种"执行一致性"比"文档完整性"难复制得多，而且在这个市场几乎没有竞品这样做。

## 为什么这件事不容易

如果 Build in Public 这么好，为什么同行不这么做？

不是他们没想到。是因为这个模式在企服行业有几条根深蒂固的阻力。

第一，**它切断了关系租金。** 公开规则意味着销售不能说"这是特批价"，管理层不能说"这是你们才有的待遇"。信息透明的代价是谈判空间归零。

第二，**它要求交付体系本身标准化。** 如果内部流程是乱麻，公开只会加速信任崩塌。公开不是策略选择，是能力门槛——你只能公开你已经做到的事情。大多数公司不是不想公开，是不敢。

第三，**它需要时间建立信任，这对创业公司是奢侈的。** 公开规则的本质是"让事实说话"，而事实需要积累。在急于证明自己的阶段，公开可能被解读为弱小。这也是为什么这个模式只见于已经跑通业务的阶段，而不是从零开始的阶段。

## 为什么这可能是对的

中国企服市场正在经历一个缓慢但不可逆的变化：买家在变得成熟。越来越多的企业采购者本身就是用过 SaaS 工具的互联网背景，他们不再接受"签 NDA 才能看文档"这种低效流程。他们想要的是：**给我看到你是怎么做的，我自己判断。**

这个变化对公开规则型的供应商是结构性利好。关系型供应商的获客成本会因为买家成熟度上升而上升——关系需要维护，维护成本不会降。规则型供应商的获客成本会因为公开档案的积累而下降——每一份公开的交付记录就是一次免费的销售展示。

这是我们选择这条路的判断基础：**市场会向信息透明的一端倾斜，虽然慢，但不可逆。**
