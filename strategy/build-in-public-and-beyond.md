# 开打闭、民主、法治、产教融合：一套逻辑的四副面孔

## 分开看，它们是四件事

从目录上看，我们的战略文档散落在不同地方：
- 「Build in Public / 开打闭」在 strategy 目录
- 「知识宪政主义」和「以政治学重构管理学」在 meta 和 organization 目录
- 「产教融合」在 qtclass 目录

它们是四个话题。但放在一起看，它们的结构一模一样。

## 共同的内核：把判断从人迁移到规则

**法治**解决的是权力问题：规则不依赖于执法者的个人判断，规则本身说了算。章程写了的就执行，没写的就不执行。不是张三宽则宽、李四严则严。

**民主**解决的是参与问题：规则的制定权不集中在少数人手里。受影响的人应该参与制定规则，至少能看到为什么这么定。

**开打闭**解决的是信息问题：规则和执行结果对利益相关方可见。客户不需要信任销售，供应商不需要信任项目经理，看公开档案就够了。

**产教融合**解决的是知识生产问题：教学案例来自真实的项目记录，不是虚构的练习。学生看到的是我们怎么做事的，不是我们想让他们看到我们怎么做事的。

四件事共享一个前提：**规则是公开的，执行是一致的，结果是可以被验证的。** 如果规则不公开，法治就变成黑箱操作——你说依法，我看不到法。如果执行不一致，民主就没有意义——参与制定的规则到了执行环节就走样。如果过程和结果不公开，开打闭就不成立。如果项目记录不公开不可用，产教融合的案例就只能是虚构的。

## 先有法治，才有开打闭

开打闭不是你想公开就能公开的。**你只能公开你已经有规则的东西。**

如果你内部没有需求拆解的标准，公开的规格书就是一封含糊的邮件。如果你内部没有验收准则，公开的交付物就没法被独立验证。如果你内部没有质量回溯流程，公开的日志就是推卸责任的吵架记录。

开打闭的条件是：内部已经法治化了。也就是说，你的团队已经在按规则运转，而不是按某人的指令运转。

这就是知识的宪法起草与公开的关系。我们先把章程写了，把规则定了，把数据模型结构化了一一这些是「立法」阶段。公不公开是第二步，让外部验证是第三步。

换个角度看：如果内部还是人治，订单靠创始人谈，交付靠项目经理盯，质量靠验收人拍板——那么公开注定是灾难。因为一旦公开，外部看到的就是你的混乱。

所以这三件事的关系是：

```
法治（规则建立） → 民主（规则协商） → 开打闭（规则公开验证）
                                  ↘ 产教融合（规则作为教学内容）
```

不是谁先谁后的时间顺序，是**依赖顺序**。开打闭依赖法治已经到位，产教融合依赖开打闭已经到位。

## 产教融合的另一种表达

产教融合过去被理解为"把企业项目带进课堂"。但更准确的理解是：**把公开的项目记录变成教学材料。**

传统产教融合的瓶颈不是企业不愿意给项目，而是项目记录不可用。一个项目做完，交付物给了客户，中间的需求变更、方案调整、踩坑复盘都在参与者的脑子里。要把这些变成教学案例，需要项目参与者专门花时间整理。这个成本没人愿意出。

如果项目本身就是公开做的呢？需求拆解在公开仓库里，伪代码确认有公开记录，交付验收有公开结果。教学不需要"整理案例"，只需要"引用已有的公开记录"。产教融合的成本从"事后整理"降到"事中引用"。

这就是开打闭对产教融合的结构性贡献：**它不是让教育更方便地获取企业项目，而是让企业项目的生产过程和结果天然就是教育素材。**

## 一套逻辑

所以这四个战略要放在一起看，不是因为它们概念上有联系，是因为它们解决的是同一个问题在不同场景下的不同表现：

| 场景 | 问题 | 解法 |
|------|------|------|
| 权力分配 | 规则靠人执行，宽严不一 | 法治：规则本身说了算 |
| 规则制定 | 少数人定规则，多数人被限制 | 民主：受影响的人参与制定 |
| 信息流通 | 供应商看不见买家标准，买家看不见供应商过程 | 开打闭：公开可验证 |
| 人才培养 | 教学案例脱离真实场景 | 产教融合：公开项目记录即教材 |

四个场景的共通解法是同一个：**把判断从人迁移到规则，把规则公开。** 这不是一个策略，是我们对所有组织问题的默认反应。
