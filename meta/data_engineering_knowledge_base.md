# 提纲区## 动机（Why）量潮在研发数据云，作为公司的 CTO，我需要负责其中的智能化架构部分，帮助业务团队提高经管数据。我们遇到的问题是，有一部分来自教科书的经验，和一部分来自具体项目的工作手册，我们要把这个作为原料，做知识图谱，用它来提高我们的自动化效率。

## 问题（What）（be specific，be 可解决、可评估）

我觉得在这个过程中，我们需要能够看到知识图谱是如何产生的，对图谱有比较精确的认识，从而可以提高知识工程的效率，方便我们在不同的问题场景中使用。

## 方案（How）（be necessary）

数据工程：保证可靠且可控，干的活对且知道为什么，所以不能纯大模型。

我们选择一个代表场景，问卷数据清洗。这个场景的主要难点是，问卷是人填写的，研究者拿到的数据很脏，我们在帮他们清洗的时候，不仅需要知道研究者的目的，还要猜测人是怎么填写的，并且匹配到清洗规则上。所以我们需要知道这个过程的推理过程是如何发生的。图谱的可视化可以帮助我们看见这个规则，从而帮助人更好地研发平台，或者使用者更好的理解，或者可以自己生产。

知识工程：提供方法和工具

大模型相比于传统知识图谱的主要优势在于，通过人机交互制作图谱，可以更好地对图谱有准确的理解。比如，在知识建模阶段，大模型可以帮助我们提炼、设计、优化知识建模。在知识抽取阶段，大模型可以更高效地抽取文本等多模态信息为实体关系。在知识计算阶段，大模型可以作为计算引擎和通用知识库。可视化工具帮助人类提高与大模型的交互效率和质量。可视化工具的作用是封装方法。

## 贡献数据工程：我们对于 Data Fabric 的范式有突破。Data Fabric 是考虑了数据血缘的图谱化，我们进一步对数据处理逻辑进行了系统的图谱化，以帮助数据工程师和分析师适应各种不同的复杂数据处理流程。未来它会成为量潮数据云的知识库原型，数据云提供的是数据工程的加工厂，会为知识图谱的迭代提供更多优质数据。

知识工程：传统的知识工程和大模型结合较少，我们为大模型系统地引入知识建模和推理流程提供了代表性的生产级探索，为这个方向的发展做出了独特贡献。未来它会成为量潮知识云的原型，知识云会用来生产包括数据云等各种各样的云的知识库的加工厂。
